# Data Source Definition

### Entities

Taken from GeoTIR research, filtered to Japan only. Each row is a unique landmark identity. The primary key is `wikimedia_url` (the Wikimedia page URL of the landmark), but an `entity_id` column was added to make it easier to reference in code. All attributes came directly from the Wikimedia page.

`entities.csv` keeps its original `category` column: GeoTIR's 5-category taxonomy, which put 90.6% of rows in `other`. Those categories were designed for a global benchmark and have no slot for the shrines, temples and mountains that dominate a Japan-filtered corpus.

`entities_taxonomy.csv` is the re-derived version, produced by `src/preprocess/taxonomy.py` from the `instance_tag` field. It adds:

- `category_fine` — normalized head noun of the instance tag (`shrine`, `bridge`, `mountain`). GeoTIR's five survive here as fine labels, so baselines stay comparable.
- `category_coarse` — curated bucket over fine labels (`religious`, `natural`, `infrastructure`, ...). 14 buckets, largest is `religious` at 27%.
- `category` — alias for one of the above, per `--category-level` (default: coarse).
- `is_landmark` — `False` for rows whose tags say they are not landmarks (Wikidata Q-IDs, prefectures, organizations). 164 rows. Flagged, never dropped.
- `classification_tags` — Shinto shrine *ranking* tags (`Shikinaisha`, `Kokuhei-sha`), which are orthogonal to physical type and would otherwise form bogus categories.

The mapping lives in `src/preprocess/taxonomy_config.yaml`, not in code. It is country-neutral: adding a country should mean adding its loanwords to `synonyms` and its head-noun collisions to `tag_overrides`.

`entities.csv` and `landmarks.csv` are deliberately left untouched as the comparison baseline; the script refuses to overwrite an existing file without `--overwrite`.

### Landmark

Also taken from GeoTIR, filtered to Japan only. Each row is a single landmark record (image + metadata). Two category columns to be aware of:

- `pred_label`: the original category from GeoTIR. Generated by a vision model (InternVL2.5 3B — need to confirm by reading the GeoTIR paper).
- `category`: joined from the entities data.

`landmarks_taxonomy.csv` is the same join re-run against `entities_taxonomy.csv` (`--landmarks`), carrying `category_fine`, `category_coarse` and `is_landmark` through. `pred_label` is left alone as a comparison baseline.

Worth knowing when comparing the two: `pred_label` disagrees with `category` structurally, not just noisily. It labels 13.4k images `arch_gate` where the entity taxonomy says `religious` — those are torii gates at Shinto shrines. The vision model describes *the image*; the taxonomy describes *the entity*.
